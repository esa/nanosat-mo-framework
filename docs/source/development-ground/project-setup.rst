=============
Project setup
=============

.. contents:: Table of contents
   :local:

The recommended way to start a Ground Application is to copy an existing example from ``sdk/examples-ground/``
and adapt it.

Available examples
------------------

- ``simple-ground`` — minimal ground application skeleton.
- ``directory-consumer`` — discovers providers through the Directory Service.
- ``set-and-command`` — sets parameter values and invokes actions on a remote app.
- ``echo`` — minimal request/response loop.
- ``camera-acquisitor-system-ground`` — drives the camera acquisitor system app from the ground.
- ``facebook`` — historical example using a non-standard transport.

Creating the project
--------------------

1. Copy an example folder under ``sdk/examples-ground/`` and rename it.
2. Update ``artifactId``, ``name``, ``description``, and ``author`` in ``pom.xml``.
3. Rename classes and packages to match.

Working directory
-----------------

A ground application reads its configuration from property files in its working directory:

- ``consumer.properties`` — consumer-side configuration (transport, encoding, timeouts). Templates are
  available under ``sdk/sdk-execution-environment/src/main/resources/ground-consumer-root/``.
- ``providerURIs.properties`` — known provider URIs. Generated by running providers; the CTT does not need
  this file because it discovers providers through the Directory Service URI supplied by the operator.
- ``settings.properties`` and ``transport.properties`` — shared transport configuration.

Set the application's working directory to a freshly created folder that contains the above files. From an
IDE, this is the "Run Configuration → Working directory" setting.

Specifying the Directory Service URI
------------------------------------

A ground application must know where to find the Supervisor's Directory Service. The SDK examples take it as
a command-line argument and pass it through to ``GroundMOAdapterImpl.retrieveProvidersFromDirectory``:

.. code-block:: bash

   java -jar my-ground-app.jar maltcp://host:port/nanosat-mo-supervisor-Directory

In an IDE, configure the URI as a program argument on the run configuration. Reading the URI from a config
file or environment variable is equally valid — ``GroundMOAdapterImpl`` does not require a particular source.

.. note::

   The ``esa.mo.nmf.centralDirectoryURI`` JVM system property is a
   **space-side** mechanism used by the Supervisor to tell child apps
   where its Directory Service lives. Ground applications do not read
   that property.
